# 这里是什么

**样例，不是模板。** 用来让你看到"每一步的产出长什么样"。

要看形状就随便打开；当模板用请用上一级 `03_模板/` 里的文件（那些是按现行规则维护的）。

## 六个样例

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| `一卡通效果图_v1.html` | 一份 HTML 多页可切换的 UI 效果图（总览 / 卡务 / 消费三页，黏土风） | **双击打开**，点左侧导航切页。这是 S2 效果图该长成的样子——不是一堆图片，是一个能点的页面 |
| `最小需求闭环示例_值班表.md` | 从需求到验收的完整链路（10 分钟能读完） | 想知道"一份完整交付长什么样"，先读这个 |
| `角色拆分对比_进销存.md` | 9 板块项目怎么分 AI（6 个席位） | 立项时对着改自己的 `00_环境.md` |
| `角色拆分对比_校园一卡通.md` | 12 板块项目怎么分 AI（9 个席位） | 同上 |

## 几个常见误解

**「效果图不是图片吗？」**
不是。这里的效果图是**能跑的 HTML**——因为调试台里"改 UI 就是改源码"，图和码是同一份东西。
出 JPG 的话，改一次要重新出图，图和码永远对不上。

**「样例里的数据是真的吗？」**
全部虚构。一卡通的学生姓名、卡号、流水都是编的，只用来演示结构与风格。

**「能直接拿样例当模板改吗？」**
能参考结构，但**别当规范**。比如效果图里那些按钮是静态的，不代表功能做完了——
这正是流程里"原型不虚假承诺"要防的坑。

## 对比图怎么来的（2026-11-15 加）

同一个项目（`<your-project-dir>`）、同一批 8 个环节、同样 8 行出处，只换说法：

- 左边：`sources` / `owning element` / `path:line` / `artifact checks` 等 12 个术语——不懂就没法填；
- 右边：出门条六格——「从哪看来的 / 那行说了什么 / 有人真看过吗」。

结论：**新版没有降低标准，只是把标准说成了人话。** 这也是本包写文档的默认要求（给新手看的，先给比喻再给术语）。

## 图鉴怎么用（2026-11-15 加）

六种图各一句话：架构图=有哪几块、时序图=谁先找谁、状态图=现在在哪一步、流程图=卡在哪一关、数据流图=数据落在谁手里、一页讲清=一页纸结论。

**只问一句话：这条线，你凭什么画的？** 答得出“第几个文件第几行”是真图；只会说“一般系统都这样”就是编的。
