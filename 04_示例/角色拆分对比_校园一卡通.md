# 角色拆分对比 · 校园一卡通（3 / 5 / 9 / 10 个 AI）

> 依据：v4.21 §7.4.1 公式 N+I+B+C+V + §10.1.1/10.1.2 并行与租约
> ⚠️ 按 CODEX 复核更正：人数按席位逐一数清，B2（验收）归 V 不归 B；集成独立；第三方对接是写码席（A 岗）
> 板块：卡务 / 账户钱包 / 消费(POS) / 门禁 / 水控电控 / 缴费 / 报表对账 / 图书馆 / 考勤 / 访客 / 管理后台 / 第三方对接（12 块）

---

## 一、依赖图

```
阶段 0（核心，共享契约，必须先冻结）
  学籍/人员对接 → 卡务管理 → 账户钱包
阶段 1（可并行，都依赖核心）
  消费(POS) ∥ 门禁 ∥ 水控电控 ∥ 缴费
阶段 2
  报表对账（依赖消费+缴费+充值）
  图书馆 / 考勤 / 访客（可选，独立）
跨端：多端联调、资金安全测试、压测
```

**业务可并行切片 N = 4**（消费 / 门禁 / 水控 / 缴费），但受 §10.1.1 安全线约束，活动写码分支实际 ≤2，**4 路必须分两波推进**。

## 二、三种 AI 数的席位分工（一席一人，逐一数清）

### 3 AI（4 个席位：A、B、C + 主理人）

| 席 | 职责 |
|---|---|
| AI-A | 写全部 12 板块（串行） |
| AI-B | 构建 + 联调 + 测试 |
| AI-C | 审 + 台账 |
| 主理人 | 门④⑤ |

### 5 AI（5 席：A1、A2、A3、B1、C1）

| 席 | 职责 |
|---|---|
| A1 | 写核心（学籍对接+卡务+账户） |
| A2 | 写消费 + 门禁 |
| A3 | **独立集成**（不写功能） |
| B1 | 构建 + 联调 |
| C1 | 审 + 台账 |
| 主理人 | 门④⑤ |

### 9 AI（最优，9 席）

`N(4) + I(1) + B(1) + C(2) + V(1) = 9`

| 席 | 归哪一角 | 职责 |
|---|---|---|
| A1–A4 | AI-A | 消费 / 门禁 / 水控 / 缴费，分两波各 2 路写码 |
| I | AI-A 内独立席 | 集成 owner，不写功能 |
| B1 | AI-B | 构建（多端） |
| B2 | **V（独立验收）** | 独立验收 + 资金对账（独立数据/口径，不共用 B1 预期值） |
| C1、C2 | AI-C | 审 / 台账 |

### 10 AI（10 席，多一个第三方对接写码席）

在 9 AI 基础上，加 **A5 = 第三方对接写码席**（微信/支付宝/学籍接口，属 AI-A 写码岗，不是联调岗）。

| 额外席 | 职责 |
|---|---|
| A5 | 第三方对接写码（沙箱；无沙箱则串行，见 §10.1.2） |

## 三、性价比结论

| AI 数 | 评价 |
|---|---|
| **3** | 能跑，12 板块串行 + 硬件联调一人扛，只够原型验证 |
| **5** | 2 路写码 + 独立集成 + 构建 + 审，核心完成后能并行，硬件联调是瓶颈 |
| **9（条件最优）** | 4 写码分两波 + 1 集成 + 1 构建 + 2 审台账 + 1 独立验收(资金对账) |
| **10** | 多 1 个第三方对接写码席，边际收益低 |

**最优 9 AI 的公式**：`N4 + I1 + B1 + C2 + V1 = 9`（B2 是验收席，归 V，不归 B）。

> **前提**：单套硬件联调台、构建联调可串行时，9 AI 是建议值；若两路写码必须同时占用独立硬件台（POS/门禁/水控），则 B 至少 2 席，总席位重新计算。

**硬约束（§10.1.2）**：生产密钥不进 worktree；第三方无沙箱时联调串行；POS/门禁/水控硬件按设备独占时间槽；测试数据按分支隔离、脱敏，不读真实学籍/交易库；资金对账必须独立数据与口径。

## 四、和进销存的关键差异

| | 进销存 | 校园一卡通 |
|---|---|---|
| 性质 | 单机业务系统 | 资金 + 硬件 + 第三方 |
| 可并行切片 N | 3 | 4 |
| 独立验收席位 V | 0（主理人签） | **1（资金对账必须独立验）** |
| 构建/联调 B | 1 | 1（多端但单构建席） |
| 审/台账 C | 1 | 2 |
| 最优 AI 数 | 6 | **9** |

**规律**：越偏"资金安全 + 硬件 + 第三方"，V 和 C 越往上加，最优 AI 数越高——不是写码需要，是**验收、审计和对账需要专人**。
