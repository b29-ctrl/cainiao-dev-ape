> 用途：把「要老板拍板 / 还没定」的问题一次列清并落盘，避免方案阶段反复回头追问，缩短需求定位时间、减少返工。
> 状态只用 `已定 / 待确认`（与流程 §17.6.1、§16.11 对齐）；来源只用 `材料` / `AI建议` / `主理人确认`。
> 决策 ID 规则：`D-{品类}-{序号}`（如 `D-YKT-01`），登记于说明书 §16.11 唯一 ID 与来源体系中作为第三类前缀（与 `B-` 功能 ID、`V-` 验收 ID 并列）。

## 使用说明（5 行）

1. 何时填：S0 需求 / S0.1 问卷阶段一出现「要不要做、有没有权限、走哪条技术前提」等会改变范围或工期的问题就登记，不等到方案阶段再回头问。
2. 谁填：AI-C 起草每行（含「不问会怎样」与推荐），主理人逐行确认或改选；`确认人` 只写实际拍板的人。
3. `阻断级 是/否`：会导致「做出来的东西作废 / 工期无法估 / 根本做不了」填 `是`；`是` 且 `待确认` 时按流程 §17.6.1 不得标定稿、不得进 S4 冻结（工具接线在 v4.60）。
4. 填完放哪：把表格内容同步进《产品功能说明书》「已知风险与待确认」章节（同一份台账，不另起第二套）；本模板文件只作格式底稿，留在技能包 `03_模板/`。
5. 交差标准：每行都要有来源与关联功能 ID，能一次追到「这条需求哪来的」；不允许空表，实在没有就写一行 `无阻断项`，省掉验收时反复核对。
