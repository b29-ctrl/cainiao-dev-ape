# 问卷生成规范 v1.2（模型驱动 · 含基准引擎与转义要求）

> 依据：`20261107_通用开发流程_v4.45.md` 第十六章
> 适用：任何品类。本规范只规定**结构、题型、校验、ID**，不规定题目内容——题目由品类对标生成
> 产出：**一个单文件 HTML**，零依赖、双击可用、底部「生成答案」输出纯文本

---

## 一、页面结构（顺序固定，不许调）

```
第 0 步  有没有现成材料？        ← 有则先收，再出定向问卷
第 1 步  选板块 → 展开 → 勾功能   ← 先骨架后细节
   └ 每个板块末尾：其他功能
   └ 板块列表末尾：其他板块
第 2 步  会翻倍工期/成本的取舍     ← 每个都带"不问会怎样"
第 3 步  明确不做（反向题）        ← 选中的是"不要"
底部     生成答案 / 复制
```

**为什么不能反**：一上来铺 40 题，用户思路乱；先给 8–9 个板块，勾谁看谁。

---

## 二、四种题型与视觉语义（必须固定，不许混用）

| 题型 | 结构 | 视觉 | 含义 |
|---|---|---|---|
| **普通选择** | `<label class="opt"><input type=radio/checkbox>` | 白底 | 选中的就是要的 |
| **风险开关** | `<div class="q risk">` | **红色左条** | 选"要"会翻倍工期或成本 |
| **反向题** | `<div class="q exclude">` | **深灰左条 + 黑底标签 + 21px 大字** | 选中的是**不要**的 |
| **AI 建议** | `<div class="advice">` | 蓝色信息条 | 我的推荐，不是你的决定 |

**风险题必须带一句「不问会怎样」**：写不出后果的题，就是没想清楚该不该问。

---

## 三、板块的固定结构（每个板块照抄这四层）

```html
<div class="blk" data-b="板块名">
  <label class="head"><input type="checkbox"><div>
    <b>板块名</b><small>一句话：这个板块干什么</small>
  </div></label>
  <div class="body">
    <!-- ① 板块级 AI 常规：由脚本自动插入，不用手写 -->
    <h4>里面要哪些功能</h4>
    <!-- ② 功能勾选，每项一个完整的用户动作 -->
    <label class="fn"><input type="checkbox" value="功能名"><div>功能名<small>为什么需要它</small></div></label>
    <!-- ③ 其他功能：脚本自动插到末尾 -->
  </div>
</div>
```

### 三层 AI 兜底

| 级别 | 位置 | 行为 |
|---|---|---|
| 全局 | 第 1 步最上 | 一次勾好所有板块的常规项 |
| 板块 | 每个板块第一行 | 只勾本板块常规项 |
| 兜底 | 板块末尾 + 列表末尾 | "其他功能" / "其他板块" 自由填写 |

**候选制（v4.6 §16.3）**：AI 兜底勾出的每一项都是**候选**，未确认不得进入答案。
**取消不清空**：用户手动勾的项，不因取消"按常规"被抹掉。

---

## 四、冲突校验（生成答案前的硬闸门）

**实现不再用伪代码，直接看 §九 的模型引擎。** 引擎行为五条（fail-closed）：

1. 未答必答题 → 阻断
2. `conflicts` 命中（按 `oid`，不按文字）→ 阻断
3. `requires` 未满足 → 阻断
4. 勾选 `待确认` 功能 → 阻断（候选未确认）
5. 未知 id / `不做` 被选 → 阻断

互斥关系写在每个选项的 `conflicts` 字段里，由生成问卷的人随模型一起给；没有配互斥关系且状态为待确认 → 阻断。

> 删除了早期 `RISK_PAIRS` 伪代码：它按文字匹配、无归属、无法 fail-closed，与模型方案冲突。全项目只保留这一套实现。

## 五、唯一 ID 与来源（v4.6 §16.11）

| 层 | 规则 | 例子 |
|---|---|---|
| 功能 | `B-{品类代码}-{板块代码}-{两位序号}` | `B-DUTY-SHIFT-01` |
| 验收 | `V-{功能ID}` | `V-B-DUTY-SHIFT-01` |
| 图 | 卡片右上角标同一 ID（小字） | — |

每项必带来源标记：`材料` / `AI建议` / `主理人确认` / `待确认`。

**规矩**：`待确认` 项不得写入说明书 v1.0 的必做功能。

## 六、答案文本格式（固定，供后续环节解析）

```
【第 1 步 板块与功能】
· 板块名：
  - B-DUTY-SHIFT-01 功能名｜来源：主理人确认｜状态：必做
  - B-DUTY-SHIFT-02 功能名｜来源：AI建议｜状态：二期
· 其他板块（自填）：xxx

【第 2 步 取舍】
· 风险1 标题：选项

【第 3 步 明确不做】
· 选项（多条用；分隔）
```

**要求**：ID 在生成时冻结，后续所有环节复用，不许重新编号。

## 七、规范自检 8 条（生成完挨条过）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 结构顺序 | 0→1→2→3 步，缺一不可 |
| 2 | 风险题 | 每题都有"不问会怎样" |
| 3 | 反向题 | 有灰底 + 黑标签 + 大字，且措辞含"不要" |
| 4 | 三级兜底 | 全局、板块、其他 都存在 |
| 5 | 冲突校验 | 有阻断时可复现，且不输出答案 |
| 6 | ID | 每项都有 `B-` 开头 ID，且不重复 |
| 7 | 来源 | 每项都标来源与状态 |
| 8 | 零依赖 | 不引 CDN、不联网、双击可开 |

## 九、模型驱动（v1.1 新增，替代手写 HTML）

**结论：不要再手写问卷页面。** 写一份 `MODEL`，用固定引擎渲染与校验。

| 层 | 谁负责 | 变不变 |
|---|---|---|
| 模型 `MODEL`（板块/功能/题目/选项/互斥） | 每个品类各写一份 | **每个项目都变** |
| 引擎（渲染 + 校验 + 生成答案） | 固定，不许改 | **永远不变** |

基准文件：`模板_问卷引擎.html`。换品类只替换 `MODEL` 那一段，其余不动。

**转义要求**：模型中任何文本（题名、说明、选项、note）一律用 `textContent` 渲染，禁止 `innerHTML` 注入——否则材料里的 HTML 会破坏页面。

模型字段见 v4.7 §16.12。五条引擎行为（缺一不可）：

1. 未答必答题 → 阻断
2. `conflicts` 命中（按 oid）→ 阻断
3. `requires` 未满足 → 阻断
4. `待确认` 候选默认不勾，勾选 = 确认采用（转主理人确认/必做）
5. `二期` 默认不勾，勾选 = 纳入本期但仍标「二期」
6. 未勾板块，其功能不计入
7. 来源×状态组合非法 → 渲染前拒绝
8. 未知 id / 重复 ID / 孤儿引用 → 阻断（fail-closed）

**反例可复现**：打开 `模板_问卷引擎.html?demo=conflict`，应看到两条阻断（跨题冲突 + 未确认功能）。

## 十、交付前的五项机器检查（v1.1 新增）

人工目测不算验收。交问卷前必须能回答：

| # | 检查 | 失败样例 | 期望 |
|---|---|---|---|
| 1 | **缺字段** | 某题没有 `why`（风险题） | 拒绝生成 |
| 2 | **重复 ID** | 两个功能都用 `B-X-01` | 拒绝生成 |
| 3 | **未答风险题** | 风险题留空 | 阻断 |
| 4 | **来源×状态组合非法** | `AI建议 × 必做`、`主理人确认 × 待确认` 等组合 | 渲染前拒绝 |
| 5 | **零依赖** | 页面引用 CDN / 联网字体 | 拒绝交付 |

> 这五项就是"陌生 AI 交的问卷合不合格"的判据；只写页面、不写校验，一律不算交付。

## 十一、选项写法纪律（v1.1 新增，二审第 7 条的落点）

**一个选项只能表达一个业务结果。** 把两件事塞进一个选项，用户按直觉勾，实施方按另一个含义做——这就是"问出错误需求"。

| ❌ 合并写法 | 问题 | ✅ 拆开写法 |
|---|---|---|
| "按最近进价（移动加权平均）" | 这是两种成本法，被当成一种 | 库存计价：`移动加权 / 先进先出 / 手工指定`；利润：`按进价算 / 不算利润` |
| "学制：中学 / 大学" | 学校阶段、节次模板、单双周、走班是四件事 | 四道独立题：阶段、节次数、单双周、是否走班 |
| "从图片或文本导入课表" | OCR 与文本解析成本差十倍 | 拆成"图片识别导入"和"文本粘贴导入"两个功能 |
| "首页不显示"当"私密" | 隐藏入口 ≠ 访问控制 | "谁能看"与"首页显不显示"分开问 |

**三条判定**：
1. 选项里出现"或"字，多半是两个能力 → 拆；
2. 选项里出现技术名词（算法、协议、框架）→ 改成业务结果，技术留给方案；
3. 勾了它以后，开发能给出**唯一**实现路径 → 合格；给不出 → 拆。

**技术实现只写在 `note` 里**（小字说明代价），不进选项标签。

---
> 一句话：**题目按品类变，结构永远这四步；没校验、没 ID、没来源的问卷，不算合规。**
